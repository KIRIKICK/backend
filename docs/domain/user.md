# USER 도메인

## 프로필 이미지 저장 정책 (MVP)

- `users.profile_image_url`은 nullable `TEXT` 컬럼으로 유지합니다.
- 이미지가 없으면 `null`, 있으면 일반 이미지 URL을 저장합니다.
- 스토리지 object key나 만료되는 signed URL은 저장하지 않습니다.
- URL과 key를 혼용하거나 문자열 접두어로 구분하지 않습니다.

이는 저장 계약입니다. 현재 엔티티가 URL 형식이나 만료 여부를 검증하는 것은 아니며,
프로필 입력 기능을 구현할 때 입력 경계에서 검증합니다.

## 확장 시점

자체 이미지 업로드와 object key 저장이 필요해질 때 명시적인 이미지 타입과 저장값 구조를 검토합니다.
현재는 이를 위한 컬럼이나 구분용 접두어를 미리 추가하지 않습니다.
기존 값은 URL이라는 계약을 유지하고, 구조를 바꿀 때 새 Flyway 마이그레이션으로 이관합니다.

## 약관 동의 기록 — 도입 보류

약관 버전 정책이 정해지지 않아 `termsVersion`과 `termsAgreedAt`의 엔티티·DB 필드 추가는 보류합니다.
기존 AUTH API 초안의 `termsVersion` 필수 입력은 확정된 연동 계약으로 취급하지 않습니다.
임의의 기본 버전을 채우거나 회원 생성 시각을 동의 시각으로 간주하지 않습니다.

실제 가입 기능을 연동하기 전에 다음 정책을 결정합니다.

- 버전 식별자가 가리키는 게시 문서와 해당 문서의 보존 방식
- 이용약관·개인정보 동의를 하나의 묶음 버전으로 관리할지 여부
- FE가 표시한 버전과 BE가 허용하는 버전을 연결하고 검증하는 방식
- 약관 개정 시 재동의 기준과 기존 동의 기록의 보존 방식

`termsAgreedAt`만 별도로 기록할 수도 있지만, 시각만으로 동의한 문서 내용을 특정할 수는 없습니다.
보류는 약관 동의가 불필요하다는 의미가 아니며, 현재 구현은 동의 버전·시각을 보존하지 않습니다.
